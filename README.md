на разработку веб-приложения для учёта и анализа личных финансов пользователей «FinTrack»
1. Общие сведения
Название проекта — FinTrack.
Тема проекта — «Разработка веб-приложения для учёта и анализа личных финансов пользователей».
Основанием для разработки является учебное задание по созданию веб-приложения с использованием современных технологий программирования.
FinTrack — это приложение, которое поможет пользователям учитывать доходы и расходы, контролировать баланс и планировать личный бюджет.
2. Назначение и цели разработки
Основная цель проекта — создание удобного приложения для ведения личного финансового учёта.
С помощью приложения пользователь сможет записывать свои доходы и расходы, распределять их по категориям, устанавливать бюджет и просматривать статистику.
Приложение предназначено для людей, которые хотят лучше контролировать свои денежные средства и планировать расходы.
3. Основные функции приложения
В приложении планируется реализовать регистрацию и авторизацию пользователей. После входа пользователь сможет перейти в личный кабинет, где будет отображаться основная информация о его финансах.
Пользователь сможет добавлять доходы и расходы, указывая название операции, сумму, категорию и дату. Также будет доступна возможность изменять и удалять ранее созданные записи.
Для удобства операции будут распределяться по категориям. Например, продукты, транспорт, покупки, развлечения и обучение. Пользователь сможет создавать собственные категории.
В приложении будет предусмотрена история операций с возможностью поиска и фильтрации по дате, категории и типу операции.
Также пользователь сможет устанавливать месячный бюджет и следить за тем, сколько денег уже потрачено. При приближении к установленному лимиту приложение будет показывать предупреждение.
Для анализа финансов будет создан отдельный раздел со статистикой. В нём планируется отображать доходы, расходы и распределение трат по категориям с помощью графиков и диаграмм.
4. Требования к интерфейсу
Интерфейс приложения должен быть простым и понятным. Основные разделы должны быть доступны через меню навигации.
В приложении должны присутствовать главная страница, раздел операций, бюджет, статистика и настройки профиля.
Необходимо предусмотреть удобные формы для добавления и изменения финансовых записей. При неправильном заполнении полей приложение должно показывать сообщение об ошибке.
Интерфейс должен корректно отображаться как на компьютерах, так и на мобильных устройствах.
5. Выбор средств реализации
Для разработки приложения планируется использовать следующие технологии:
React — для создания пользовательского интерфейса и отдельных компонентов приложения.
TypeScript — для написания более понятного и структурированного кода.
Vite — для запуска и сборки клиентской части приложения.
Node.js и Express.js — для создания серверной части и обработки запросов.
MongoDB — для хранения информации о пользователях, операциях, категориях и бюджетах.
Mongoose — для взаимодействия серверной части с базой данных.
CSS — для оформления страниц и адаптации интерфейса.
Recharts — для создания графиков и диаграмм.
Git и GitHub — для хранения исходного кода и отслеживания изменений проекта.
Выбранные технологии позволяют разделить приложение на клиентскую и серверную части, что упростит его разработку и дальнейшее сопровождение.
6. Требования к базе данных
В базе данных необходимо хранить информацию о пользователях, финансовых операциях, категориях и бюджетах.
Для пользователей будут сохраняться имя, электронная почта и защищённый пароль.
Для финансовых операций необходимо хранить название, сумму, дату, тип операции и категорию.
Для бюджета будет сохраняться установленная пользователем сумма и месяц, на который он рассчитан.
Данные каждого пользователя должны храниться отдельно, чтобы исключить доступ к чужой финансовой информации.
7. Требования к безопасности и надёжности
Приложение должно проверять данные, которые вводит пользователь, и не допускать сохранения некорректных значений.
Пароли пользователей должны храниться в зашифрованном виде с использованием хеширования. Доступ к личному кабинету должен осуществляться только после авторизации.
Необходимо предусмотреть защиту данных пользователей и проверку прав доступа при работе с финансовыми операциями.
Также рекомендуется регулярно создавать резервные копии базы данных.
8. Требования к внедрению
После завершения разработки приложение необходимо подготовить к запуску.
Для работы потребуется серверная среда с поддержкой Node.js, база данных MongoDB и доступ к интернету.
Планируется использовать MongoDB Atlas для хранения данных и подходящий облачный хостинг для размещения клиентской и серверной частей.
Перед запуском необходимо установить зависимости, настроить подключение к базе данных и проверить работу основных функций.
После этого приложение можно разместить в интернете и предоставить пользователям доступ через браузер.
9. Тестирование приложения
Перед сдачей проекта необходимо проверить правильность работы всех основных функций.
Следует протестировать регистрацию и авторизацию, добавление, изменение и удаление операций, работу категорий, бюджета и статистики.
Отдельно необходимо проверить правильность расчёта баланса и сохранения данных.
Также следует проверить отображение приложения на разных устройствах и убедиться, что пользователи не могут просматривать чужую информацию.
Все найденные ошибки необходимо исправить и повторно проверить работу приложения.
10. Этапы разработки
Разработка проекта будет проходить в несколько этапов.
Сначала необходимо изучить требования и подготовить техническое задание. Затем продумать структуру приложения и внешний вид страниц.
После этого будет создана клиентская часть, серверная часть и база данных. Далее планируется реализовать основные функции приложения и связать все компоненты между собой.
После завершения разработки необходимо провести тестирование, исправить ошибки, подготовить приложение к размещению и оформить документацию.
Исходный код проекта будет размещён в GitHub.
11. План сопровождения приложения на два года
После запуска приложения необходимо продолжать проверять его работу, исправлять ошибки и улучшать существующие функции.
В первые три месяца планируется наблюдать за работой приложения, исправлять ошибки и собирать отзывы пользователей.
С четвёртого по шестой месяц предполагается улучшить интерфейс, формы добавления операций и систему поиска.
С седьмого по девятый месяц планируется доработать статистику, графики и отображение расходов по категориям.
С десятого по двенадцатый месяц необходимо проверить безопасность приложения, обновить используемые библиотеки и провести повторное тестирование.
С тринадцатого по пятнадцатый месяц планируется улучшить работу с бюджетом и категориями.
С шестнадцатого по восемнадцатый месяц необходимо проверить историю операций и при необходимости оптимизировать работу базы данных.
С девятнадцатого по двадцать первый месяц планируется улучшить отображение приложения на мобильных устройствах и учесть предложения пользователей.
В последние три месяца необходимо провести итоговую проверку, исправить оставшиеся ошибки и обновить документацию.
Для получения отзывов можно использовать форму обратной связи. Пользователи смогут сообщать о найденных ошибках и предлагать новые функции. Все обращения необходимо рассматривать, определять их важность и при необходимости вносить изменения в приложение.
После каждого обновления следует проверять работу изменённых функций, чтобы новые изменения не приводили к появлению ошибок.

13. Порядок приёмки проекта
Готовое приложение должно соответствовать требованиям, указанным в техническом задании.
При проверке необходимо убедиться, что пользователь может зарегистрироваться, добавлять и изменять финансовые операции, создавать категории, устанавливать бюджет и просматривать статистику.
Также проверяется правильность сохранения данных, расчёта баланса и работы интерфейса.
Проект считается завершённым после реализации основных функций, исправления критических ошибок и подготовки приложения к демонстрации.
14. Заключение
В результате выполнения проекта планируется создать веб-приложение FinTrack для учёта и анализа личных финансов.
Приложение позволит пользователям контролировать доходы и расходы, планировать бюджет и просматривать статистику.
Разработка будет выполнена с использованием React, TypeScript, Node.js, Express.js и MongoDB.
После завершения работы приложение будет протестировано и подготовлено к размещению. В дальнейшем предусмотрено сопровождение продукта в течение двух лет, включающее исправление ошибок, обновление функций и обработку отзывов пользователей.
